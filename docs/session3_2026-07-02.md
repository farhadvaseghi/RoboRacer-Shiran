## Part 2 — What changed since the `Hardware` branch

### New code (on dev-box branch `camera-costmap`, based on `Hardware` — NOT pushed, NOT on the car yet)

- **New package `roboracer_camera/`** — self-contained. Node `depth_to_scan`
  converts the ZED depth map into `/camera_scan`, a synthetic `LaserScan` of
  obstacles that stand **above/below the LiDAR's single 11 cm slice** (a box on a
  chair, a shelf lip, a torso). Colour-independent (never reads RGB — right for
  white walls / dark floor). Publishes in its own `camera_scan` frame, so it's
  independent of the ZED wrapper's TF tree. Geometry unit-verified on the dev box.
- **`roboracer_estimation/config/nav2_params_real.yaml`** — the ONE change to an
  existing file: added `camera` as a second `observation_source` on the
  `obstacle_layer` of **both** costmaps (`observation_sources: scan camera` + a
  `camera` block on `/camera_scan`). Additive and non-destructive — delete the
  word `camera` to roll back to LiDAR-only.
- **`roboracer_camera/DEPLOY.md`** — ZED SDK install + deploy + on-site tuning
  runbook.
- **`docs/session3_2026-07-02.md`** — this file.

### Rationale
In a corridor/wall race the 2-D LiDAR already owns the walls (SLAM + costmap).
The camera's only non-redundant contribution is above-plane obstacles, so it is
wired in as an *extra costmap obstacle source*, not as a wall detector. Nothing
in the planner/controller/estimation changes.

### Operational state (not code)
- Runtime isolation convention: **ROS_DOMAIN_ID=7** via `~/shiran_env.sh`.
- New map `corridor_new` (in the backup).

## Part 5 — Step-by-step runbooks

> **Every one of our terminals starts by joining domain 7.** Either
> `source ~/shiran_env.sh` (also sources our workspace) or `export
> ROS_DOMAIN_ID=7`. Connect from the laptop on the `roboracer` Wi-Fi:
> `ssh roboracer@192.168.50.10`.

### 0. Monday quickstart — restore our stack to the car
Run from the **dev box** (has internet + LAN):
```bash

#    paths, so the built install/ works with NO rebuild)
scp ~/roboracer_ws/car_backups/shiran_stack_2026-07-02.tar.gz roboracer@192.168.50.10:/tmp/
ssh roboracer@192.168.50.10 'cd ~ && tar xzf /tmp/shiran_stack_2026-07-02.tar.gz && rm /tmp/shiran_stack_2026-07-02.tar.gz && ls -d ~/roboracer_ws ~/rr ~/rr_maps ~/shiran_env.sh'

# 2) fix the clock (car boots to 1970). Use the CURRENT UTC time:
NOW=$(date -u +"%Y-%m-%d %H:%M:%S")
ssh roboracer@192.168.50.10 "echo '<shared-login-password>' | sudo -S -p '' date -u -s '$NOW'; date"
```
Then on the car verify: `source ~/shiran_env.sh` → should print
`ROS_DOMAIN_ID=7  ws=sourced`, and `ros2 pkg executables roboracer_estimation`

> Alternative (if you'd rather not restore the tarball): re-deploy from git via

### A. SLAM mapping (redo / finish the map)
Open SSH sessions; each starts with `export ROS_DOMAIN_ID=7`.
```bash
# T1 — drivers (LiDAR + VESC + joystick + mux)
export ROS_DOMAIN_ID=7 && ~/t_stack.sh
# T2 — SLAM (slam_toolbox async mapping on /scan)
export ROS_DOMAIN_ID=7 && ~/rr/rr_slam.sh
# T3 — record the run (optional, recommended)
export ROS_DOMAIN_ID=7 && ~/rr/rr_record.sh corridor2
```
Drive slowly (hold **LB** deadman), continuously, cover the whole corridor and
return to start to close the loop. `/odom` + `odom→base_link` only publish while
driving, so keep moving. Save while T2 still runs:
```bash
export ROS_DOMAIN_ID=7 && ~/rr/rr_savemap.sh corridor_new   # ~/rr_maps/corridor_new.{pgm,yaml}
```
Snapshot to eyeball coverage anytime: `export ROS_DOMAIN_ID=7 && ~/rr/rr_snap.sh`
→ `~/rr_maps/live.png`. Then `Ctrl-C` T2. Health: `~/rr/rr_doctor.sh`.

### B. Autonomous run — LiDAR-only (Nav2 end-to-end)
`t_stack.sh` (T1) must be running; SLAM (T2) must be **stopped**.
```bash

export ROS_DOMAIN_ID=7
source ~/roboracer_ws/install/setup.bash
ros2 launch roboracer_estimation autonomous_real.launch.py \
    map:=/home/roboracer/rr_maps/corridor_new.yaml
```
Then (T3): set the start pose and goal (see `hardware/guide.md` §5). Roughly:
- place the car at the SLAM origin (start pose defaults to 0,0,0), or set it with
  RViz **2D Pose Estimate** / the `rr_initpose.sh` helper if present;
- verify `map→odom` TF appears and the scan overlaps the map in RViz;
- send a goal with RViz **Nav2 Goal**. Speed is capped 0.5 m/s in
  `nav2_params_real.yaml` — don't raise it until a clean lap.
- **Joystick overrides autonomy at all times** (mux prio 100 vs 10) — your stop.

## Part 6 — Key facts & gotchas

- **Shared login** `roboracer` — no per-group isolation on disk; the other group
  knows the same password. That's why our stack is kept off the car between
  sessions (backup on the dev box) rather than "hidden" on it.
- **Car is offline; the dev box is the bridge** for all downloads/deploys.
- **Clock = 1970 at every boot** → fix first each session or TF/SLAM/Nav2 break.
- **Domain 7** in every one of our terminals, or nodes won't see each other.
- **`/odom` + `odom→base_link` only publish while a drive command flows** — idle
  car shows no odom; not a bug.
- **Gamepad is the safety override** and must be charged; brownouts = phantom
  stops that also stall SLAM.
- **`ros2 topic hz` needs ≥8 s** on this setup to beat DDS discovery latency;
  short windows falsely read 0 Hz.
- Real frames are plain (`base_link`/`odom`/`laser`); wheelbase 0.25 m; speeds
  capped 0.5 m/s for first runs.
